# DSA and Codeforces Track

## Purpose

Use three different practice modes. They overlap, but they are not the same.

### 1. Learning mode
Study one pattern, solve related problems, and write what made each problem difficult.

### 2. Contest mode
Practice speed, implementation, mathematical creativity, and decision-making under time pressure.

### 3. Interview mode
Explain the brute force, improve it, justify correctness, analyze complexity, and test edge cases aloud.

## Weekly minimum

- [ ] 2 focused DSA study sessions
- [ ] 1 Codeforces contest or virtual contest
- [ ] Upsolve every contest problem that was realistically within reach
- [ ] 1 interview-style problem solved aloud
- [ ] Update the mistake log

## Problem-solving process

1. Restate the problem in your own words.
2. Identify constraints and target complexity.
3. Work through small examples manually.
4. State the brute-force approach.
5. Search for a known pattern only after thinking independently.
6. Prove why the optimized idea works.
7. Implement cleanly.
8. Test boundaries and counterexamples.
9. Record the lesson.

## Topic order

### Stage 1: Foundations
- Arrays, strings, sorting
- Complexity

- Prefix sums
- Two pointers
- Sliding window
- Binary search
- Recursion basics

### Stage 2: Core interview structures
- Linked lists
- Stack and queue
- Trees and BST
- Heap and priority queue
- Graph BFS/DFS
- Backtracking
- Greedy fundamentals
- Dynamic programming fundamentals

### Stage 3: Competitive-programming depth
- Number theory
- Combinatorics
- Bit manipulation
- DSU
- Shortest paths
- MST
- Fenwick and segment trees
- Trie

## Mistake categories

- Misread the statement
- Missed a constraint
- Wrong complexity estimate
- Could not identify the pattern
- Correct idea, incorrect proof
- Implementation bug
- Overflow or type bug
- Off-by-one/indexing bug
- Failed to test edge cases
- Panicked or switched ideas too quickly

## Interview readiness standard

A topic is interview-ready when I can:

- [ ] recognize common variants
- [ ] explain a brute-force solution
- [ ] derive an optimized solution
- [ ] justify correctness
- [ ] state time and space complexity
- [ ] write compiling code without external help
- [ ] test the implementation aloud
- [ ] revisit it weeks later without memorizing exact code

## Healthy targets

Prefer depth over raw counts. A reasonable two-year result is:

- 250–400 deeply reviewed interview/DSA problems
- consistent contests and upsolving
- a personal error log
- regular mock interviews during the final six months

Do not sacrifice projects, CS fundamentals, sleep, or university performance merely to inflate a problem count or rating.
