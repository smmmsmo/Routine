# Weekly Routine

Default target: **15–18 focused hours per week outside university**.

## Standard university week

| Day | Main work | Time |
|---|---|---:|
| Monday | DSA pattern study + 2 problems | 2 h |
| Tuesday | Backend/full-stack learning or project | 2–3 h |
| Wednesday | Codeforces contest/virtual contest | 2 h |
| Thursday | Core CS: OS, DBMS, networks, or OOP | 2 h |
| Friday | Project implementation | 2–3 h |
| Saturday | Project deep-work + contest upsolving | 3–4 h |
| Sunday | Mathematics + review + next-week planning | 2 h |

Adjust the days around classes, but preserve the categories.

## Minimum viable week

Use this during exams, illness, or unusually busy weeks:

- [ ] 2 DSA problems
- [ ] 1 project session of at least 90 minutes
- [ ] 1 CS-foundation review session
- [ ] 20-minute weekly review

The goal is to maintain continuity, not force full intensity.

## Daily study-session structure

### 90-minute learning session

1. **5 min:** define the exact outcome
2. **30 min:** learn one concept actively
3. **45 min:** solve/build without following step-by-step instructions
4. **10 min:** write a summary and the next action

### 2-hour project session

1. **10 min:** choose one issue/task
2. **80 min:** uninterrupted implementation
3. **20 min:** test, refactor, and document
4. **10 min:** commit and write the next task

## Current phase allocation

### Months 1–6
- DSA/Codeforces: 40%
- Development: 40%
- CS fundamentals: 15%
- Review/career: 5%

### Months 7–15
- DSA/Codeforces: 30–35%
- Development/projects: 45–50%
- CS fundamentals: 15%
- Review/career: 5%

### Months 16–21
- DSA/Codeforces: 30%
- Standout project/open source: 45%
- CS/system design: 20%
- Career: 5%

### Months 22–24
- Coding interviews: 40%
- Applications and behavioral prep: 20%
- Project maintenance: 15%
- CS/system design review: 25%

## Rules that protect consistency

- Do not start more than one major course at the same time.
- Do not run more than one major project at the same time.
- Finish weekly upsolving before entering another contest when possible.
- Commit project work in small, meaningful units.
- Keep one notebook or digital file for mistakes and lessons.
- Every fourth week may be lighter and used for revision.
- Sleep and university deadlines outrank an arbitrary streak.

## Weekly checklist

### DSA and contests
- [ ] Studied one defined pattern
- [ ] Solved and reviewed planned problems
- [ ] Attended one contest or virtual contest
- [ ] Upsolved missed problems
- [ ] Added mistakes to error log

### Engineering
- [ ] Learned one practical concept
- [ ] Shipped one visible project improvement
- [ ] Wrote tests or tested manually
- [ ] Made meaningful Git commits
- [ ] Documented one technical decision

### CS fundamentals
- [ ] Studied one focused topic
- [ ] Explained it without notes
- [ ] Connected it to a real application

### Reflection
- [ ] What did I finish?
- [ ] What remained unfinished, and why?
- [ ] What mistake repeated?
- [ ] What is next week's single most important result?

## Sample weekly goal

> By Sunday night, I will implement registration and login with validation, solve eight two-pointer problems, attend one Codeforces contest and upsolve it, and explain process-versus-thread from memory.

That is better than a vague goal such as “study programming.”
