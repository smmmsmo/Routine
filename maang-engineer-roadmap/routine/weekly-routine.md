# Combined Weekly Routine

> **Separate mathematics-only plan:** The new [MATH-Routine](../../MATH-Routine/README.md) allocates **21 hours/week** to mathematics alone (6 phases, **312 weeks / 6,552 planned hours**; Phase 0 is 16 weeks / 336 hours). This page's **19–23 hours/week** is the **legacy combined engineering schedule including only 5–7 math hours**. These two schedules are **alternatives, not additive targets**. Reallocate other activities explicitly if adopting the 21-hour math plan.


Default target: **19–23 focused hours per week outside university**.

This is ambitious. During heavy academic weeks, reduce volume but preserve continuity.

## Standard university week

| Day | Main work | Time |
|---|---|---:|
| Monday | Mathematics concept session + DSA pattern practice | 2.5–3 h |
| Tuesday | Backend/full-stack learning or project | 2–3 h |
| Wednesday | Mathematics exercises + Codeforces contest/virtual contest | 2.5–3 h |
| Thursday | Core CS: OS, DBMS, networks, or OOP | 2 h |
| Friday | Mathematics concept/derivation + project implementation | 2.5–3.5 h |
| Saturday | Project deep work + contest upsolving | 3–4 h |
| Sunday | Mathematics review/hard problem + weekly review and planning | 2–3 h |

Adjust the days around classes, but preserve these categories:

- mathematics;
- DSA/problem solving;
- software development;
- CS fundamentals;
- review and planning.

See [the detailed mathematics routine](math-routine.md) for session formats and mastery checks.

## Weekly allocation

- Mathematics: **5–7 hours**
- DSA and Codeforces: **4–6 hours**
- Development and projects: **6–8 hours**
- CS fundamentals: **2–3 hours**
- Review and career preparation: **1 hour**

Do not attempt maximum hours every week. A repeatable 18-hour week beats one heroic 30-hour week followed by collapse.

## Minimum viable week

Use this during exams, illness, or unusually busy weeks:

- [ ] one 45-minute mathematics concept review;
- [ ] five math exercises and one old mistake re-solved;
- [ ] two DSA problems;
- [ ] one project session of at least 90 minutes;
- [ ] one CS-foundation review session;
- [ ] 20-minute weekly review.

The goal is to maintain continuity, not force full intensity.

## Daily study-session structures

### 90-minute mathematics learning session

1. **5 min:** recall the previous lesson without notes.
2. **30 min:** learn one concept actively.
3. **20 min:** reproduce definitions or derivations.
4. **25 min:** solve exercises unaided.
5. **10 min:** summarize and record confusion.

### 90-minute engineering learning session

1. **5 min:** define the exact outcome.
2. **30 min:** learn one concept actively.
3. **45 min:** solve/build without step-by-step instructions.
4. **10 min:** write a summary and next action.

### 2-hour project session

1. **10 min:** choose one issue/task.
2. **80 min:** uninterrupted implementation.
3. **20 min:** test, refactor, and document.
4. **10 min:** commit and write the next task.

### 90-minute difficult-problem session

1. Work unaided for 45–60 minutes.
2. Record examples, observations, and failed approaches.
3. Read only a small hint if genuinely stuck.
4. Complete the solution where possible.
5. Rewrite the clean reasoning later and schedule a re-solve.

## Two-year emphasis

### Months 1–6

- Mathematics: foundation repair, proof basics, combinatorics, number theory
- DSA/Codeforces: strong regular practice
- Development: C++ refresh, Git/Linux, JavaScript/TypeScript foundations
- Goal: rebuild fundamentals without rushing into AI

### Months 7–12

- Mathematics: recurrences, graphs, single-variable calculus, mathematical computing
- Development: backend, PostgreSQL, React, first serious project
- CS fundamentals: OS, DBMS, networking, OOP
- Goal: finish Year 1 with one deployed project and reliable calculus foundations

### Months 13–18

- Mathematics: linear algebra and probability
- Development: production engineering, Docker, testing, CI/CD
- DSA: contests, interview patterns, and selected mathematical problems
- Goal: connect matrix/probability ideas to practical code

### Months 19–22

- Mathematics: statistics, multivariable calculus, optimization
- Development: standout project and system design
- Career: internship/open-source/team experience
- Goal: derive and implement core ML mathematics

### Months 23–24

- Mathematics: ML integration, research reading, and capstone
- Coding interviews: timed practice and mocks
- Applications and behavioral preparation
- Project maintenance and documentation
- Goal: graduate with evidence of both engineering skill and mathematical maturity

## Rules that protect consistency

- Do not start more than one major mathematics course at a time.
- Do not start more than one major engineering course at a time.
- Do not run more than one major project at a time.
- Use videos for explanation, books for precision, and exercises for mastery.
- Finish weekly upsolving before entering another contest when possible.
- Commit project work in small, meaningful units.
- Keep separate error logs for mathematics and programming.
- Every fourth week may be lighter and used for revision.
- Sleep, health, and university deadlines outrank an arbitrary streak.

## Weekly checklist

### Mathematics

- [ ] Completed planned sections.
- [ ] Solved routine exercises.
- [ ] Attempted at least one unfamiliar problem.
- [ ] Reproduced one derivation or proof.
- [ ] Updated the mathematics error log.
- [ ] Re-solved one previous mistake.

### DSA and contests

- [ ] Studied one defined pattern.
- [ ] Solved and reviewed planned problems.
- [ ] Attended one contest/virtual contest or completed equivalent practice.
- [ ] Upsolved missed problems.
- [ ] Added mistakes to the programming error log.

### Engineering

- [ ] Learned one practical concept.
- [ ] Shipped one visible project improvement.
- [ ] Wrote tests or tested manually.
- [ ] Made meaningful Git commits.
- [ ] Documented one technical decision.

### CS fundamentals

- [ ] Studied one focused topic.
- [ ] Explained it without notes.
- [ ] Connected it to a real application.

### Reflection

- [ ] What did I finish?
- [ ] What remained unfinished, and why?
- [ ] What mistake repeated?
- [ ] What should be reduced or postponed?
- [ ] What is next week's single most important result?
