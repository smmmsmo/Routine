# Interview and Career Preparation

Begin light preparation early, then increase intensity during the final six months.

## Technical interview skills

- [ ] Clarify ambiguous requirements before coding
- [ ] Explain a brute-force approach first
- [ ] Derive an optimized solution logically
- [ ] State assumptions
- [ ] Prove or justify correctness
- [ ] Analyze time and space complexity
- [ ] Write clean, compilable C++
- [ ] Test normal, boundary, and adversarial cases
- [ ] Respond calmly to hints
- [ ] Communicate while thinking without narrating every tiny thought

## Core CS revision

### Operating systems
- Processes, threads, scheduling
- Concurrency, locks, race conditions, deadlocks
- Memory, paging, virtual memory
- Filesystems and system calls

### Databases
- SQL and joins
- Keys and normalization
- Indexes and query plans
- Transactions, ACID, isolation, locks

### Networks
- TCP versus UDP
- DNS
- HTTP/HTTPS
- Cookies, sessions, CORS
- Proxies, load balancers, WebSockets

### Software design
- OOP and composition
- Interfaces and abstraction
- SOLID and common patterns
- Testing and dependency management
- API and data-model trade-offs

## New-grad system design process

1. Clarify users and requirements.
2. Define scale and important quality attributes.
3. Propose APIs.
4. Design the data model.
5. Draw the high-level architecture.
6. Identify bottlenecks and failure points.
7. Add caching, queues, replication, or partitioning only when justified.
8. Explain alternatives and trade-offs.

Practice designs such as:

- URL shortener
- rate limiter
- notification service
- chat system
- file storage service
- coding-practice platform
- news feed
- job queue

## Behavioral story bank

Prepare 8–10 truthful stories using Situation, Task, Action, Result, and Reflection.

- [ ] A difficult bug
- [ ] A project that failed or changed direction
- [ ] A disagreement with a teammate
- [ ] Leadership without formal authority
- [ ] Learning something quickly
- [ ] Receiving difficult feedback
- [ ] Taking ownership
- [ ] Managing multiple deadlines
- [ ] Improving quality or performance
- [ ] Helping another person succeed

Each story should clarify what **I** did while giving teammates fair credit.

## Resume target

Keep it to one page for new-grad applications.

- [ ] Education and expected graduation
- [ ] Technical skills grouped honestly
- [ ] Experience, internship, research, or leadership
- [ ] Two strongest projects
- [ ] Competitive programming only when it adds evidence
- [ ] Quantified results when genuinely measured
- [ ] No skill bars or inflated claims
- [ ] No long objective paragraph
- [ ] Consistent formatting and no spelling errors

## Strong project bullet formula

> Built **what** for **whom/problem**, using **important technologies**, resulting in **measured or concrete outcome**, while handling **meaningful engineering challenge**.

Avoid fake numbers. Concrete architecture or functionality is better than invented impact.

## GitHub readiness

- [ ] Professional profile README
- [ ] Two strongest repositories pinned
- [ ] Clear setup instructions
- [ ] Screenshots/demo where useful
- [ ] Architecture and trade-offs documented
- [ ] Issues and pull requests show real workflow
- [ ] No secrets, generated junk, or broken setup
- [ ] Commit history is understandable

## Experience ladder

Pursue these in parallel with the roadmap:

1. University team projects done seriously
2. Club or nonprofit software work
3. Research assistance
4. Freelance work with real users
5. Open-source contributions
6. Internships

The title matters less than credible evidence of collaboration, ownership, and shipped work.

## Application strategy

Apply broadly across:

- MAANG and other global technology companies
- strong regional software companies
- product startups
- fintech and infrastructure companies
- new-grad and internship programs
- backend, full-stack, platform, and general SDE roles

Do not wait until feeling 100% ready. Begin applying when the fundamentals and at least one strong project are present.

## Final 12-week interview routine

Weekly:

- [ ] 8–12 carefully reviewed coding problems
- [ ] 2 coding mock interviews
- [ ] 1 system-design practice
- [ ] 1 behavioral practice
- [ ] 1 CS-foundation revision block
- [ ] Continue applications and follow-ups
- [ ] Review every rejection/interview for actionable lessons

## Graduation-ready standard

- [ ] Can solve common medium interview problems while communicating
- [ ] Can explain the two main projects deeply
- [ ] Can answer foundational OS, DBMS, network, OOP, and SQL questions
- [ ] Can design a modest web service and discuss trade-offs
- [ ] Has truthful behavioral stories
- [ ] Has completed repeated mock interviews
- [ ] Applies broadly and tracks the process professionally
